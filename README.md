# PharmacyHezam — نظام إدارة مشتريات الصيدلية

واجهة عربية RTL لإدارة الأصناف والموردين وفواتير الشراء والنواقص ومقارنة أسعار الشراء. تعمل النسخة الحالية محلياً داخل المتصفح باستخدام IndexedDB.

## التشغيل

1. ارفع ملفات المشروع إلى مستودع GitHub.
2. فعّل GitHub Pages من إعدادات المستودع واختر الفرع `main` ومجلد الجذر `/`.
3. افتح رابط GitHub Pages في متصفح حديث.
4. استيراد ملفات XLS/XLSX يتطلب اتصالاً بالإنترنت لتحميل SheetJS من CDN.

## الوظائف الحالية

- لوحة تحكم وإحصاءات أساسية.
- قاعدة أصناف تتضمن الاسم العلمي والتركيز والشكل الدوائي ووحدة الشراء والوحدة الأساسية ومعامل التحويل.
- استيراد فواتير XLS/XLSX مع معاينة قبل الحفظ ومحاولة اكتشاف أعمدة الصنف والكمية والسعر والبونص والخصم والتشغيلة والانتهاء.
- إظهار سعر الشراء الأصلي والسعر الفعلي بعد البونص في معاينة الفاتورة وسجل الشراء.
- حساب السعر الفعلي وفق المعادلة: `(إجمالي السطر - الخصم) / (الكمية المدفوعة + البونص)`.
- حفظ الفاتورة وبنودها وسجل التدقيق ضمن معاملة IndexedDB واحدة لتجنب حفظ فاتورة دون بنودها.
- منع التكرار باستخدام المورد + رقم الفاتورة + التاريخ عند توفر رقم الفاتورة.
- إدارة النواقص ومنع التكرار للصنف النشط بنفس الوحدة.
- مراجعة مشتريات الفواتير المطابقة للنواقص بالاسم والوحدة، ثم تطبيق الخصم بعد تأكيد المستخدم مع منع استخدام كمية الشراء نفسها مرتين.
- مقارنة السعر الأصلي والسعر بعد البونص، وتطبيق معامل التحويل إلى الوحدة الأساسية عندما تتطابق وحدة الفاتورة مع وحدة الشراء المسجلة.
- إنشاء مسودة طلبية شراء من الكميات المتبقية في قائمة النواقص.
- دليل الموردين وسجل المشتريات.
- تصدير واستعادة نسخة JSON مع التحقق من بنية النسخة وتنفيذ الاستعادة في معاملة واحدة.

## طريقة احتساب البونص وملاحظات التسعير

السعر الفعلي للوحدة = `(إجمالي تكلفة السطر - الخصم) ÷ (الكمية المدفوعة + كمية البونص)`.

يفترض النظام أن إجمالي السطر المدخل/المستورد هو إجمالي قبل خصم الخصم المنفصل. يجب التحقق من تنسيق فاتورة المورد؛ إذا كان الإجمالي يتضمن الخصم بالفعل، فلا بد من تعديل مصدر البيانات أو إعداد الاستيراد لتجنب خصم الخصم مرتين.

المقارنة على الوحدة الأساسية لا تتم إلا عند تعريف وحدة الشراء ومعامل التحويل بشكل صحيح في قاعدة الأصناف، وعندما تتطابق وحدة الفاتورة مع وحدة الشراء. خلاف ذلك يعرض السعر بوحدة الفاتورة دون تحويل.

## حدود مهمة قبل الاستخدام التشغيلي

- محلل Excel يتعرف على أسماء أعمدة شائعة فقط. قد تتطلب بعض أنظمة الفوترة ضبطاً خاصاً أو خريطة أعمدة يدوية؛ يجب اختبار ملفات حقيقية متعددة قبل الاعتماد.
- مطابقة النواقص تعتمد حالياً على تطابق الاسم بعد التطبيع النصي والوحدة تماماً؛ لا توجد مطابقة ذكية تقريبية ولا دمج تلقائي للأسماء المتشابهة.
- الطلبية الناتجة مسودة مجمعة من النواقص؛ لا تتضمن بعد توزيعاً تلقائياً حسب المورد أو أسعار الموردين أو الطباعة المتقدمة أو دورة اعتماد.
- البيانات محفوظة في IndexedDB على المتصفح والجهاز الحالي فقط. لا توجد مزامنة سحابية أو تعدد مستخدمين أو صلاحيات أو تشفير للبيانات المحلية.
- حذف بيانات المتصفح أو تغيير الجهاز قد يؤدي إلى فقد البيانات؛ صدّر نسخة احتياطية دورياً واحتفظ بها خارج الجهاز.
- لا تعتمد النظام منفرداً في إدارة مخزون صيدلية أو بيانات مالية فعلية قبل اختبار القيم المستوردة ومطابقة الأسعار والوحدات والنسخ الاحتياطي على نسخ من بيانات حقيقية.
